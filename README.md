# ИДЗ-4: супермаркет с TCP-сервером и клиентами-наблюдателями

Проект сохраняет модель супермаркета из ИДЗ-3, вариант 8, и добавляет сетевой уровень TCP.

## Состав

- `supermarket_named` - процессы симуляции из ИДЗ-3: генератор покупателей, две кассы и процесс публикации состояния. Модель использует POSIX shared memory и именованные POSIX-семафоры.
- `supermarket_server` - TCP-сервер. Принимает снимки состояния от одного процесса `publisher`, раздаёт их всем подключённым наблюдателям.
- `supermarket_client` - независимый TCP-клиент с таблицей состояния супермаркета.
- `run_network.sh` - локальный запуск сервера, симуляции и одного наблюдателя.
- `tests/run_network_tests.sh` - интеграционный тест с отключением и повторным подключением наблюдателя.

## Сборка

Требуется Linux, GCC, GNU Make и POSIX API.

```bash
make clean
make all
```

Сборка создаёт четыре исполняемых файла: `supermarket`, `supermarket_named`, `supermarket_server` и `supermarket_client`. Первые два сохраняют реализации ИДЗ-3 с неименованными и именованными семафорами.

## Быстрый запуск на одном компьютере

```bash
make run-network
```

Либо с другой конфигурацией и портом:

```bash
PORT=5555 SERVER_IP=127.0.0.1 BIND_IP=0.0.0.0 ./run_network.sh config.txt
```

`run_network.sh` запускает TCP-сервер, инициализирует разделяемую память, запускает две кассы, генератор и publisher, а также подключает один локальный клиент-наблюдатель. По завершении моделирования сервер остаётся запущенным и хранит последний снимок. Нажатие `Ctrl+C` останавливает сервер.

## Запуск на нескольких компьютерах

Все процессы симуляции, обращающиеся к POSIX shared memory, должны выполняться на одном компьютере. TCP-сервер и клиенты-наблюдатели могут находиться на других компьютерах.

**Компьютер A - сервер:**

```bash
./supermarket_server 0.0.0.0 5555
```

**Компьютер B - симуляция:**

```bash
./supermarket_named init config.txt
./supermarket_named publisher <IP_КОМПЬЮТЕРА_A> 5555 &
./supermarket_named cashier 0 &
./supermarket_named cashier 1 &
./supermarket_named generator &
```

После окончания процессов симуляции:

```bash
./supermarket_named cleanup
```

**Любой компьютер C, D, ... - клиент-наблюдатель:**

```bash
./supermarket_client <IP_КОМПЬЮТЕРА_A> 5555
```

Можно запустить несколько экземпляров клиента. Остановка клиента по `Ctrl+C` не останавливает сервер или симуляцию. Повторный запуск клиента подключает его заново; сервер сразу отправляет ему последний сохранённый снимок.

```bash
make test          # 19 регрессионных проверок ИДЗ-3 (включая длительные сценарии)

```

## Протокол

Протокол текстовый, построчный: каждое сообщение заканчивается `\n`.

1. Publisher открывает TCP-соединение и отправляет `PUBLISHER supermarket-simulation`.
2. Каждый наблюдатель отправляет `OBSERVER observer`.
3. Publisher с заданным интервалом отправляет строку `S|...` со временем модели, статистикой, содержимым обеих очередей и состоянием кассиров.
4. Сервер проверяет тип сообщения, сохраняет последний снимок и рассылает его всем наблюдателям.
5. При подключении нового наблюдателя сервер сначала отправляет приветствие, затем последний сохранённый снимок.

Сервер использует `poll()` и неблокирующие сокеты. Медленный клиент не задерживает остальных: при заполнении его выходной очереди устаревшие снимки заменяются самым свежим. Сервер обслуживает до 64 TCP-подключений одновременно (один publisher и до 63 наблюдателей).

## Ограничения

- Поддерживается один publisher на одну запущенную модель супермаркета.
- Состояние передаётся снимками, а не полным журналом каждого события. При медленном клиенте промежуточные снимки могут пропускаться, но последнее состояние сохраняется.
- Протокол не реализует шифрование и аутентификацию; запускать сервер следует в доверенной учебной сети или за сетевым экраном.
